## Diagnostic Steps
1. Record the full stop code, device model, asset number and any storage-driver, BIOS, imaging or firmware change made immediately before the failure.
2. Confirm the BitLocker recovery key is available before changing firmware or boot settings.
3. In firmware, compare the storage-controller mode with the approved organisational baseline. Record the current value before making any change.
4. Enter Windows Recovery Environment and inspect whether the physical disk and Windows volume are visible.

{% capture kb_command_1 %}
diskpart
list disk
list volume
exit
{% endcapture %}
{% include command.html shell="cmd" label="Windows Recovery Command Prompt" command=kb_command_1 %}

5. If the Windows volume is visible, perform a read-focused NTFS scan before attempting repair.

{% capture kb_command_2 %}
chkdsk C: /scan
{% endcapture %}
{% include command.html shell="cmd" label="Windows Recovery Command Prompt" command=kb_command_2 %}

## Remediation Steps
1. If the issue started immediately after an approved storage-mode or storage-driver change, reverse only that documented change.
2. Use Windows Recovery to roll back the most recent approved storage driver or update when evidence points to it.
3. If recovery policy requires reimaging, confirm protected user data and recovery material are available before applying the approved enterprise image.
4. Stop remediation and escalate if the system disk disappears, reports hardware failure, or encryption recovery cannot be completed safely.

## Rollback Steps
1. Restore the firmware storage-controller value recorded during diagnosis if a test change does not improve the boot state.
2. Do not alter partitions, encryption configuration or boot records beyond the approved recovery action.
3. If a remediation step worsens the condition, return to the last documented boot/storage state and escalate with the recovery outputs.

## Verification Steps
1. Boot Windows successfully.
2. Restart the device and confirm a second clean boot without the stop error.
3. Confirm the system disk is visible and no new critical storage-health event is reported.
4. Confirm the user can sign in and access the expected system volume.

## Escalation Path
1. Escalate to Endpoint Engineering if the BitLocker recovery key is unavailable, storage health is failing, the disk is absent in recovery, critical data is at risk, or approved recovery actions fail.
2. Include the stop code, model, asset number, BIOS storage mode, recent changes, disk/volume output and every recovery action already attempted.
