## Safety first
Do not repeatedly power-cycle a device with signs of disk failure. Confirm the BitLocker recovery key is available before firmware or boot changes.

## Steps
1. Record the full stop code, device model, asset number and any driver, BIOS, imaging or storage changes immediately before failure.

2. In firmware, compare the storage controller mode with the organisation's standard. Do not randomly switch AHCI/RAID modes.

3. Enter Windows Recovery Environment and inspect the disk.

{% capture kb_command_1 %}
diskpart
list disk
list volume
exit
{% endcapture %}
{% include command.html shell="cmd" label="Windows Recovery Command Prompt" command=kb_command_1 %}

   <div class="expected"><strong>Expected result:</strong> The system disk and Windows volume are visible. A missing disk suggests firmware, controller or hardware failure.</div>

4. Run a read-focused file-system check first. Use repair options only under your recovery policy.

{% capture kb_command_2 %}
chkdsk C: /scan
{% endcapture %}
{% include command.html shell="cmd" label="Windows Recovery Command Prompt" command=kb_command_2 %}

5. Remove or roll back the most recent storage driver/update using approved recovery tools, or restore the last known-good enterprise image where data is protected.

## Verification
Windows boots twice without a stop error and storage health checks show no new critical events.
